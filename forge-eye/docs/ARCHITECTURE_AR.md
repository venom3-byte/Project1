# Forge Eye — الخطة المعمارية للمحرر الجديد

## قرار البنية

نحوّل القواعد الحساسة للسلامة الهندسية إلى Rust ونبنيها كـWASM للمتصفح؛ ونستخدم المكتبة نفسها في الاختبارات الأصلية وربما مضيف سطح المكتب. لا نعني بعبارة «مكتوب بـRust» أن المتصفح لا يحتاج HTML/CSS أو واجهة JavaScript للتعامل مع DOM والملفات. الأفضل هو فصل النواة الحتمية عن الواجهة وعن طبقة GPU.

## الطبقات المستهدفة

1. **Forge Eye Core (Rust):** مخطط المشروع، العقد، التحويلات، تاريخ Undo/Redo، نظام الأوامر، التحقق من الشبكات، triangulation، visual hull، تحويل وحدات القياس، الاستيفاء والمنحنيات.
2. **WASM boundary:** واجهة JSON صغيرة موثقة، تحقق من الأحجام والمدخلات، أخطاء واضحة بدلاً من panic، وعدم نسخ مصفوفات ضخمة أكثر من اللازم.
3. **Viewport/GPU:** محول Mesh مستقل عن Rust core؛ اكتشاف WebGPU وتوفير مسار WebGL2 عند الحاجة. حفظ الأصول لا يعتمد على جلسة GPU.
4. **Workspace UI:** Viewport/Hiearchy/Inspector/Timeline/Graph Editor/Asset Browser، تخطيطات قابلة للتغيير، لمس وهاتف، واختصارات لوحة المفاتيح.
5. **Media/modeling pipeline:** صور مرجعية معايرة، إزالة الخلفية منفصلة عن الصورة الأصلية، contour editing، إنشاء الحجم من front/side/top، تنظيف الشبكة ثم فحصها قبل اعتمادها.
6. **Animation:** Dope Sheet وGraph Editor، ثم tangents قابلة للتحرير، rig/constraints/NLA على مراحل منفصلة.
7. **AI adapters:** تقسيم المخطط إلى أجزاء، كشف الرموز/الأبعاد، اقتراح مقاطع هندسية، image-to-3D/segmentation كخدمات اختيارية قابلة للتبديل؛ كل نتيجة لها مصدر وثقة وإمكانية تعديل بشري.
8. **Verification:** cargo tests + wasm build + Chromium desktop/mobile + اختبارات عكسية للـimport/export + صور مقارنة + قياس الأداء والذاكرة.

## ما نُفّذ في هذه المرحلة

- إنشاء workspace Rust مستقل `forge-eye-core` و`forge-eye-wasm`.
- تنفيذ تحقق contour، triangulation، extrusion شبكي، وvisual hull فوكسلي من منظورين أو ثلاثة.
- واجهة WASM تعتمد JSON وتعيد شبكة قابلة للتحويل إلى Mesh داخل الـViewport.
- اختبارات Rust للمدخلات غير السليمة والنتائج والهندسة والتسلسل.

## حدود الدقة الحالية

Visual hull ليس نموذجاً نهائياً دقيقاً: هو تقاطع أحجام silhouette ويخفق في استعادة التجاويف والأسطح المخفية. يجب أن تسبق استخدامه الدائم معايرة القياسات والمحاور وتتبّع الحدود جيداً، وأن تتبعه مرحلة remeshing/topology وتنظيف ومراجعة بشرية. لا نقدم ضمان «خطأ غير مرئي» أو ادعاء أن النموذج أصبح مكافئاً كاملاً لـBlender 5 أو Unreal 5.

## شروط الانتقال إلى النسخة الرئيسية

لا استبدال شامل قبل: نجاح اختبارات النواة وWASM؛ تحميل wasm من المسار العام؛ إثبات عمليات الملفات والمشاهد؛ تكافؤ الوظائف المسجلة؛ الأداء على الهاتف؛ وجود rollback؛ ومراجعة المستخدم لمعاينة منفصلة.

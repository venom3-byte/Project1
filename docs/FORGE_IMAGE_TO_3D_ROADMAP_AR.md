# Forge — خطة هندسة Image-to-3D العملية

**الحالة الحالية:** خطة تنفيذ واختبار؛ لم يُدمج بعد مشغّل استدلال Image-to-3D في المحرر.  
**المبدأ الأساسي:** Forge يحتاج خط إنتاج قابلًا للفحص، لا زرًا يرسل صورة ثم يعرض Mesh غير موثوق.  
**التنسيق الداخلي:** glTF/GLB، الوحدات بالمتر، Y للأعلى، ومعرّفات ثابتة للأصول والمهام.

## 1. فصل ثلاثة أنواع من النمذجة

### A. توليد سريع من صورة واحدة
مناسب للمفاهيم والأصول التقريبية: قطعة أثاث، صخرة، غرض، أو شكل أولي للسيارة. النموذج يتنبأ بالأجزاء التي لا تظهر في الصورة؛ لذلك لا يمكن اعتباره مسحًا هندسيًا مطابقًا أو مرجعًا قياسيًا للأبعاد.

- **Stable Fast 3D (SF3D):** مسار مرجعي خفيف نسبيًا لإنتاج Mesh مع UV وخامة من صورة واحدة. المستودع الرسمي يذكر أن CPU مدعوم، وأن الإعداد الافتراضي يستهلك نحو 6 GB VRAM؛ الأداء على CPU أو الهاتف ليس مساويًا لتشغيل GPU.
- **Microsoft TRELLIS.2:** مرشح عالي الجودة عندما توجد بيئة GPU مهيأة؛ مستودعه الرسمي يصف نموذجًا من 4B ومعالجة خامات PBR. متطلبات المشروع المنشورة تستهدف Linux وNVIDIA GPU بذاكرة لا تقل عن 24 GB، والأرقام السريعة المنشورة مقاسة على H100. ليس خيارًا يمكن افتراض تشغيله مجانًا أو مباشرة على الهاتف.

مصادر التنفيذ الأساسية:
- SF3D: https://github.com/Stability-AI/stable-fast-3d
- TRELLIS.2: https://github.com/microsoft/TRELLIS.2
- وصف TRELLIS.2 من Microsoft Research: https://www.microsoft.com/en-us/research/workbench/project/trellis

### B. إعادة بناء من صور متعددة
هذا هو المسار الأفضل للأجسام الواقعية عند توافر صور متداخلة من عدة زوايا. تجمع Forge الصور مع زاوية الكاميرا/المنظور إن توفرت، ثم تشغّل photogrammetry أو نموذج multi-view. النتيجة تبقى بحاجة إلى تنظيف الشبكة والخامات ومقارنة الأبعاد.

صور أمام/جانب/خلف فقط دون تداخل أو معايرة لا تضمن إعادة بناء مثالية. يجب توضيح جودة الإدخال للمستخدم قبل بدء المهمة.

### C. نمذجة دقيقة من مخططات ومقاسات
مخصصة للطائرات والسيارات والقطع الهندسية. هنا لا نعتمد على Mesh تخميني من صورة واحدة بوصفه «النسخة الأصلية». يستخدم Forge:
1. مراجع أمامية وجانبية وعلوية، بعد قص الخلفية وتثبيت المقياس.
2. نقاط تحكم ومقاطع بدن/سطوح وجناح أو هيكل، مع مسافات مرجعية معلومة.
3. إنشاء هندسة قابلة للتحرير ثم مقارنة silhouette من كل اتجاه مع المرجع.
4. إدخال مكوّنات مولّدة منفصلة فقط بعد مطابقتها، مع الاحتفاظ بمصدر وقياسات كل جزء.

هذا المسار أنسب لمشروع F-16؛ صورة منظور واحد ليست كافية لاستنتاج هندسة البدن أو مواقع الأدوات الداخلية بدقة.

## 2. المعمارية المقترحة

1. **Forge UI / Asset Lab:** يستقبل الملفات ويعرض المراجع، القصّ، mask، قائمة الزوايا، طريقة التوليد، مستوى الجودة، وحدود المضلعات/دقة الخامة.
2. **Job contract محايد للمزود:** JSON موثق، لا يعتمد على API خاص بنموذج لغة. يشمل `taskId`، بصمات الصور، اختيار النمط، المقياس، المحاور، الحدود المطلوبة، وحالة المهمة.
3. **Inference adapter:** واجهة خلفية توحّد استدعاء:
   - مشغّل SF3D محلي أو على GPU؛
   - مشغّل TRELLIS.2 لخيار الجودة العالية؛
   - مشغّل multi-view/photogrammetry؛
   - مشغّل blueprint/parametric.
4. **معالجة الأصول:** استلام GLB إلى مساحة مؤقتة ثم تدقيقه وإصلاحه. لا يُحقن ملف غير متحقق مباشرة في المشهد.
5. **Quality gates:** تشخيص هندسة وخامات ومقاسات، ثم رندر تلقائي من زوايا ثابتة ومقارنة بالمرجع.
6. **استعراض وموافقة:** يعرض Forge المصدر والنتيجة والفرق. المستخدم يختار إدراج الأصل؛ لا يستبدل Mesh سابقًا بصمت.
7. **تصدير:** GLB مكتمل بمواد مضمّنة، وmanifest مصدر/نموذج/مقياس/أبعاد/عدد المثلثات/نتائج QA.

واجهة API الخلفية هنا واجهة بين Forge ومشغّل الاستدلال، وليست اعتمادًا على مزوّد محادثة بعينه. يمكن تشغيل المحوّل محليًا أو على GPU بعيد. لا يتطلب ذلك مفتاح OpenAI/Claude، لكن نموذج التوليد نفسه يحتاج حسابات/موارد حوسبة إذا لم يُشغّل محليًا.

## 3. عقد مهمة مقترح

```json
{
  "schemaVersion": 1,
  "taskId": "generated-by-forge",
  "mode": "single-image",
  "sourceImages": [
    {
      "assetId": "source-asset-id",
      "sha256": "content-hash",
      "view": "front-three-quarter",
      "maskAssetId": null
    }
  ],
  "target": {
    "format": "glb",
    "unit": "meter",
    "upAxis": "Y",
    "forwardAxis": "Z",
    "maxTriangles": 120000,
    "textureResolution": 2048
  },
  "qualityProfile": "balanced",
  "adapter": "auto"
}
```

هذا عقد مقترح للمرحلة القادمة، وليس endpoint منفذًا حاليًا. يجب أن تكون قيم `adapter` و`qualityProfile` قائمة مسموحة؛ ولا يسمح العقد بمسار ملف اعتباطي أو أمر shell.

## 4. بوابات التحقق قبل قبول أي Mesh

### بوابة الملفات
- التحقق من MIME والحجم وبصمة SHA-256 قبل الاستدلال.
- رفض أرشيف أو GLB غير صالح، ومراجع خارجية غير مضمّنة، وخامات مفقودة.
- حدّ زمني وحدّ للحجم والذاكرة مع إمكانية إلغاء المهمة.

### بوابة هندسية
- قراءة GLB وإعادة فتحه بعد المعالجة.
- فحص bounding box والمقياس والمحاور والأصل والمسافة عن مركز النموذج.
- تسجيل الرؤوس والمثلثات والأجزاء المنفصلة وUV ومواد PBR والعظام/الأنيميشن إن وجدت.
- رصد الرؤوس غير المنتهية، والأوجه المنعدمة، والنورمال المفقودة، والمواد غير المدعومة، والأجزاء الخارجة عن الحجم المتوقع.
- توليد LOD وcollision proxy كمنتجات مشتقة، مع إبقاء ملف المصدر دون تغيير.

### بوابة بصرية
- إخراج لقطات أمام/خلف/جانب/أعلى/أربع زوايا منظور بإضاءة وكاميرا ثابتتين.
- عرض المرجع بجانب النتيجة مع silhouette overlay؛ لا تُعامل مقارنة الصورة الواحدة على أنها دليل على صحة الجانب غير المرئي.
- سجلّ score منفصل لكل اتجاه، ولا يُضبط حدّ قبول نهائي إلا بعد بناء مجموعة اختبارات مرجعية معروفة.
- يجب أن يستطيع الفاحص رفض النموذج تلقائيًا وإرجاع سبب مفهوم مثل «المقياس بعيد عن المرجع» أو «السطح الخلفي غير مدعوم بالصور».

## 5. خطة تنفيذ مرحلية

| المرحلة | التنفيذ | معيار القبول |
|---|---|---|
| 0. أساس الأصول | توثيق الصور، القصّ، masks، المقياس، وmanifest المصدر | إدخال عدة صور مع بصمات وmetadata قابلة لإعادة الفحص |
| 1. أول مشغّل | دمج SF3D خلف adapter؛ استيراد GLB وتخزين السجل | أصل واحد من صورة؛ لا أخطاء تحميل؛ تصدير GLB وإعادة استيراده بنجاح |
| 2. مراقبة الجودة | تدقيق هندسي + لقطات 6 اتجاهات | تقرير ثابت لكل نتيجة، ولا قبول تلقائي عند فشل التحميل أو غياب الخامات |
| 3. جودة عالية | إضافة TRELLIS.2 إلى عامل GPU اختياري | نجاح مهمة end-to-end على بيئة GPU معلومة؛ قياس الزمن والذاكرة والحجم |
| 4. صور متعددة | التقاط الزوايا وتسجيلها ثم إعادة بناء متعددة الصور | المقارنة البصرية على مجموعة اختبار متعددة المناظر |
| 5. نمذجة مرجعية دقيقة | overlays للمخططات، خطوط/مقاطع قابلة للضبط وربط المقاسات بالهندسة | نموذج مثل الهيكل الخارجي للطائرة لا يُقبل إلا بعد مقارنة أبعاده وصوره في عدة اتجاهات |
| 6. الإنتاج | إصلاح الشبكات، LOD، collision، manifests، export profile | اختبار استيراد/تصدير + replay بصري + regression على كل أصل معتمد |

## 6. ملفات يجب إضافتها عند بدء التنفيذ

- `src/shared/imageTo3D/types.ts`: عقد المهمة والحالات وأنواع الإدخال/النتيجة.
- `src/shared/imageTo3D/validate.ts`: تحقق payload ومصادقة الصيغ/الحدود.
- `src/editor/ImageTo3DDialog.tsx`: واجهة الإدخال والمراجع والحالة والإلغاء.
- `server/forge/image-to-3d-adapter.mjs`: عقد الاستدلال الموحد، مع adapters منفصلة للنماذج.
- `scripts/validate-generated-glb.mjs`: بوابة GLB بعد الاستدلال.
- `__tests__/image-to-3d.test.ts`: حالات payload غير صالح، إلغاء المهمة، إخفاق الاستدلال، GLB مفقود الخامات، وإعادة فتح المصدر.

**قاعدة تنفيذ:** لا يُعلن Image-to-3D «مكتملًا» عند إضافة الحوار أو عند إرجاع ملف. يلزم تشغيل مشغّل حقيقي، استيراد الناتج، حفظ الأدلة، والنجاح في بوابات الهندسة والرندر.
